# 人体运动：工作模式与调试模式

[English](HUMAN_PIPELINE_GUIDE.md)

本文区分正常工作路线和诊断实验，并指出已有接口与尚未完成的集成。

<a id="accepted-working-mode-contract"></a>

## 已接受的工作模式契约

作者于 2026-09-16 明确本契约，取代此前混合诊断与正常使用的说明。区分请求行为和已实现接口；策略更新不证明新端到端模型运行。

工作模式输入视频，重建完整请求时长中**所有出现的人物**。选择困难片段、特定人物或匹配对照属于调试。房间仍用 Pi3X 参考和可编辑 Blender 工作流。

职责标签：

- **固定计算**：已实现计算消费显式输入/配置。
- **配置计算**：配置包含的指定阶段执行，不自行决定加入。
- **智能体判断**：GPT-6 理解源/场景语义或审查最终结果，要明确说明，不能当作脚本。
- **集成待完成**：已有组件尚未完整实现工作模式，不声称有可执行生产命令。

<a id="working-mode-stages"></a>

## 工作模式阶段

| 阶段 | 决策/正常行为 | 输入 → 输出 | 现有实现与边界 |
| --- | --- | --- | --- |
| 1. 发现所有人物 | 自动工作阶段，不让智能体选偏好人物/片段 | 全视频 → 人物轨迹/初始化，包括后进入者 | SAMURAI 需初始化；全人物发现/初始化/关联待集成。samurai_reconstruct.py 消费一个人物和提供掩码；重复单人物调用不证明全发现。 |
| 2. 跟踪和可见性 | 自动跟踪器策略，无 GPT-6 出场/遮挡检查点 | 跟踪 → 掩码与 active/inactive 范围 | 有效 SAMURAI 输出为运行信号：无有效结果时隐藏，不虚构可见延续。恢复人物属关联/分段。track_lifecycle.py 当前为审查过的终止前缀契约，任意自动区间需集成。 |
| 3. 估计运动 | 各活跃人物段固定模型执行 | 掩码/裁剪、视频、同镜头 Pi3X 相机旋转 → ViTPose 与 GVHMR | samurai_reconstruct.py 配 samurai_tracking.py、camera_tracks.py。工作模式称估计；重新估计是调试重跑，不是强制第二遍。 |
| 4. 过滤二维观测 | 固定阈值，不由 GPT-6 编写可见区间 | 关键点置信度 → 可用掩码 | 接受配置阈值以上。depth_observations.py 的 min_keypoint_score 默认 0.5，但仍需审查区间/诊断输入，工作模式需拆除依赖。保留数值有效性和匹配人物掩码/深度检查，不加语义审查门。 |
| 5. 放入房间 | 必需固定计算 | 人体、有效观测、Pi3X 深度/相机、共同房间基 → 每段刚性旋转/平移 | depth_observations.py 实现固定尺寸深度锚定和刚性摆放，身体尺度 1；房间制作/基准备为独立责任。 |
| 6. 修正接触位置 | 当前请求路线包含，不让智能体另决定是否额外修轨迹 | 对齐人体、接触事件/体表块、有限表面 → 候选 | align_depth_trajectory.py、root_constraints.py、full_scene_constraints.py 的 smooth_contact/smooth_scene_contact 解位置偏移，时间正则可平滑修正。不前置独立尺度/漂移平滑实验。事件/目标仍需源语义判断，无已建立全自动检测。 |
| 7. 组装和交付 | 脚本组装/渲染，最终智能体审查另标 | 房间、所有人物、活跃区间 → 场景、全长视频、可选比较页 | body.py、ensemble.py、render_clip.py、build_portal.py；保留保存场景、视频时间和全解码检查。接触/风格在结果后检查，不是强制对齐前诊断。 |

SAMURAI 无结果是请求的**运行时隐藏规则**，不代表跟踪丢失科学证明人物离开；继续前无需 GPT-6 区分，不改为强制手工生命周期审查。实现须明确置信度/有效性和分段/关联行为。

置信阈值是接受的观测过滤，不是校准的解剖可见性保证，不能换名重引 GPT-6 审查每个髋/肩区间。

当前范围保留 GVHMR 关节运动/尺寸。刚性初始摆放后仅修接触位置。独立轨迹缩放、深度漂移平滑、单独垂直偏移搜索、Kimodo 生成/编辑和 IK，除再次请求均在范围外。平滑接触曲线是求解器一部分，不是独立决策阶段。

优先级为**接触 → 源动作/风格 → 图像对齐**。源相对目标仍需人体表面块、物体面、获取/释放区间；代码消费声明，此解释须标智能体判断，不能称全自动。位置求解不证明关节、准确接触面积、摩擦或平衡。

<a id="debug-mode"></a>

## 调试模式

调试用于方法开发/报告失败调查，可选一两个挑战片段/人物，对比跟踪/相机，检查身份/遮挡或可选修复，不是强制工作步骤。

| 调试任务 | 脚本/职责 |
| --- | --- |
| 选择人物/困难时间窗 | 实验智能体判断 |
| 换跟踪/相机后重估 | samurai_reconstruct.py，新输入/推理，不重贴旧缓存标签 |
| 原 ViTPose 重投影/原生地面诊断 | export_motion_quality.py、audit_native_ground.py，调试/结果后分析，不强制估计后立即运行 |
| 跟踪生命周期/可见区间审计 | 源检查及 track_lifecycle.py/depth_observations.py 审查 schema |
| 轨迹缩放/独立漂移/固定垂直对比 | align_depth_trajectory.py，显式实验配置 |
| Kimodo 补全/接触编辑 | complete_motion.py、contact_edit.py，显式实验；全过程可见部分约束和动作文本 |
| 数值包/候选预览 | human_inspection.py、render_inspection.py |
| 源/对照/候选网页 | build_portal.py，对比是调试展示，不是视频重建前提 |

历史 32/42 实验属此模式。2026-09-15 渲染的四个完整视频是已拒绝的固定关节接触位置试验，不是新 Kimodo 样本；接触、浮空和姿态问题继续保留，新策略不改变旧结果。

<a id="implemented-components-versus-missing-integration"></a>

## 已实现组件与缺失集成

单人物 SAMURAI/GVHMR 启动器、Pi3X 相机适配、深度对齐数学、接触位置求解、Blender 导入和实验运行器已实现。以下仍**不是经过验证的自动全人物流水线**：

1. 全输入人物发现、初始化和关联。
2. 将跟踪器自动有效区间贯穿估计、再出现和最终可见性，取代旧审查终止前缀。
3. 只按置信选观测，去除深度生成器手工区间/诊断前提。
4. 不靠显式语义准备生成接触事件/表面。

不要虚构 --mode working 或声称文档消除代码依赖。本次记录契约、分离调试接口；实现和真实视频验证须各自证据。

`bash tools/human_experiments/run.sh` 执行/恢复/缓存指定命令图，不发现人物、选修正、创建接触语义或提供缺失集成，见[运行器接口](../tools/human_experiments/RUNNER.md)。

[跟踪/轨迹](HUMAN_TRACKING_AND_TRAJECTORY.md)和[自动化](HUMAN_AUTOMATION.md)保留旧调试接口/证据；不能把旧审查要求当作上方工作模式。
